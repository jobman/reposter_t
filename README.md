# reposter_t

Telegram-бот принимает медиа в личных сообщениях, складывает его в SQLite-очередь и
публикует в приватный канал по равномерному расписанию. Он отправляет файлы заново по
Telegram `file_id`, поэтому имя исходного автора и исходная подпись не переносятся.
Единственная подпись публикации — кликабельное слово `join`.

## Безопасный запуск

По умолчанию действуют сразу две блокировки:

1. `POSTING_ENABLED=false` — жёсткий серверный запрет.
2. Настройка `paused=true` в SQLite — управляемая пауза.

В discovery-режиме бот может принимать контент и обнаруживать канал, но физически не
может ничего в него опубликовать.

## Первый запуск

1. Скопировать `.env.example` в `.env`, заполнить `BOT_TOKEN` и случайный
   `SETUP_SECRET`, оставить `POSTING_ENABLED=false`.
2. Запустить `python -m reposter_bot`.
3. В личном чате с ботом выполнить `/claim SETUP_SECRET`.
4. Добавить бота администратором приватного канала с правом публикации.
5. Вручную опубликовать в канале одно тестовое сообщение. Бот только запомнит `chat_id`.
6. В личном чате проверить `/status`, затем выполнить `/usechannel`.
7. Для рабочего режима установить `POSTING_ENABLED=true`, перезапустить сервис и
   только после проверки выполнить `/resume`.

## Команды

- `/status` — режим, канал, очередь и ближайший слот.
- `/queue` — первые 20 элементов очереди.
- `/delete ID` — удалить элемент, который ещё не опубликован.
- `/schedule 19:00 02:00 10` — окно и количество публикаций.
- `/pause` и `/resume` — остановить/возобновить расписание.
- `/usechannel` — назначить последний обнаруженный канал целевым.

При настройках по умолчанию окно длится 7 часов, а 10 слотов идут каждые 42 минуты:
19:00, 19:42, …, 01:18. Конец окна 02:00 не включён.

## Локальная разработка

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/ruff check .
.venv/bin/pytest -q
```

## Развёртывание

Workflow `.github/workflows/deploy.yml` запускается при каждом push в `main` на
self-hosted runner. Сначала выполняются lint и тесты, затем создаётся отдельный release,
атомарно обновляется ссылка `current` и перезапускается systemd-сервис. Файл `.env` и
SQLite находятся в `/home/nebula/apps/reposter_t/shared` и не меняются деплоем.
